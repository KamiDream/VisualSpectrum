# VisualSpectrum · 环形频谱可视化

把**系统正在播放的声音**变成桌面上的一圈**随音乐起伏的环形频谱**：
CRT 显示器那种荧光辉光、从频谱条顶端逸出的**散射粒子**、中心一圈套一圈的**同心环**（不填充，颜色用你自定义的色标）+ X 形油光。

它是常驻后台的小工具，有**两种模式**：

| 模式 | 长什么样 |
|---|---|
| **顶层**（默认） | 浮在所有窗口最上面，**鼠标穿透**（点上去落到后面的窗口，不挡事） |
| **壁纸** | 贴到桌面壁纸层，被所有窗口盖住，只在"看桌面"时可见（Windows 会挂进桌面层） |

设置**只有几项**（大小 / 数量 / 条高 / 强度 / 连线 / 旋转 / 模式），其余都交给自动增益 ——
不用调增益、不用挑频段。

---

## 1. 快速开始

需要一个 Python 环境（推荐 conda，环境名随意，下面用 `VSp`）：

```bash
conda env create -f environment.yml         # 建出 VSp 环境（含全部依赖）
# 或者：自己建一个 env 再 pip install -r requirements.txt

conda run -n VSp python run.py              # 启动
```

启动后默认**顶层模式**，屏幕中央就会出现一圈频谱。配置页在
<http://127.0.0.1:8770>（托盘菜单里也有「打开配置页」）。

命令行参数：

| 参数 | 作用 |
|---|---|
| `--debug` | 把日志也打到终端（默认只写文件），排错用 |
| `--selfcheck` | 只体检不启动：音频后端、WebEngine、配置文件位置 |
| `--no-tray` / `--no-config-server` | 不起托盘 / 不起配置页 |
| `--high-fps` | 解锁 Chromium 帧率上限（动画更顺，代价是更费 CPU/GPU） |
| `--config 路径` | 用另一份配置文件（默认在用户数据目录） |
| `--port 8770` | 配置页端口 |

**日志在哪里**：源码运行 → `./logs/visualspectrum.log`（每次启动重写，全量记录）；
打包运行 → 用户数据目录（`--selfcheck` 会打印确切路径）。

## 2. 设置

配置页 <http://127.0.0.1:8770>（保存后**当场生效**，不用重启）：

| 项 | 含义 | 范围 |
|---|---|---|
| **大小** | 环的外径占**屏幕短边**的百分比（可 >100，让环溢出屏幕） | 5 ~ 200 |
| **数量** | 环上频谱块的个数 —— 越多越细腻，也越费性能 | 4 ~ 512 |
| **条高** | 频谱条**最长**是环半径的百分之多少；>100 则不封顶、条会冲出环外（越细长） | 5 ~ 500 |
| **强度/灵敏度** | 整体电平放大倍数 —— 调大更灵敏（同样的声音条更高） | 10 ~ 1000 |
| **低/中/高音占比** | 三块**各自归一化**后再乘的倍数 —— 低音因此也有起伏，不再永远打满 | 0 ~ 400 |
| **连线** | 把各条**顶端的中心点**用细线依次相连（一圈荧光脉冲线） | 开 / 关 |
| **旋转** | 整圈是否缓慢自转（关掉就定格） | 开 / 关 |
| **颜色** | 按频率**低 → 高**的一段色标（1~8 色，中间自动插值） | 一组 `#RRGGBB` |
| **背景** | 整块背景的颜色 + **不透明度**（0 = 全透明，桌面直接透出来）；颜色默认黑 | `#RRGGBB` / 0 ~ 100 |
| **CRT 效果** | 扫描线 + 暗角（**只在背景不透明度 > 0 时可开**） | 开 / 关 |
| **余晖** | 荧光拖尾的强度（0 = 不留余晖，越大光尾越长） | 0 ~ 100 |
| **粒子** | 散射粒子的**速度 / 寿命**倍数（100 = 原样） | 20 ~ 400 |
| **鼓点扩散** | 低频一记重击从容心炸一圈**全屏扩散**粒子：开关 + 灵敏度 / 速度 / 寿命 | 开/关 · 0~100 · 20~400 |
| **模式** | `顶层`（浮最上、鼠标穿透）/ `壁纸`（贴桌面底层） | — |

音频（新开了一栏，主要为了蓝牙耳机）：

| 项 | 含义 | 取值 |
|---|---|---|
| **来源** | 抓系统声音（回环）/ 关闭（只放演示波形） | `系统声音` / `关闭` |
| **捕获设备** | 抓哪个设备的回环（默认输出 / 指定某个） | `自动` / 具体设备 |
| **启动延迟** | 启动后等多久再打开音频设备 —— 错开启动瞬间的设备抢占 | 0 ~ 10000 ms |

> **蓝牙耳机上音乐被中断？** 打开回环捕获时，某些蓝牙耳机会被系统从 A2DP（高音质立体声）
> 切到通话模式，音乐就停了 —— 这是系统/驱动的行为。⚠ **如果音乐正放\*在蓝牙耳机上\***，
> 要抓到它就**必须**在耳机上开捕获，这个切换基本避不开；此时只能：把**捕获设备**选到
> 另一个设备（前提是声音确实从那里出），或把**来源**设为「关闭」，或改用在有线设备上播放。

性能（`render`）：

| 项 | 含义 |
|---|---|
| **高刷新率** `render.high_fps` | 解锁 Chromium 的帧率上限，让高刷屏跑到 120fps。⚠ **改这一项要重启**才生效 |

> 动画本身是**帧率无关**的（平滑系数按时间算），所以 60fps 和 120fps 手感一致；
> 而且我们自己把绘制**限速在 120fps**——就算 Chromium 解锁后 rAF 飙到几千 Hz，也不会狂烧 CPU/GPU。

配置就存在一个 JSON 文件里（`~/.config/visualspectrum/config.json`，Windows 是
`%APPDATA%\VisualSpectrum\config.json`）：

```json
{
  "version": 1,
  "appearance": {
    "size": 55, "count": 96, "height": 48,
    "intensity": 100, "bass": 100, "mid": 100, "treble": 100,
    "link": true, "rotate": true,
    "colors": ["#7EE7FF", "#B37BFF", "#FF6FD8"],
    "bg_color": "#000000", "bg_opacity": 0, "crt": true, "afterglow": 60,
    "particle_speed": 100, "particle_life": 100,
    "burst": true, "burst_sensitivity": 55, "burst_speed": 100, "burst_life": 100,
    "mode": "top"
  },
  "audio": { "source": "system", "delay_ms": 600, "device": "auto" },
  "render": { "high_fps": false }
}
```

手改这个文件也行 —— 运行中的程序靠 mtime 发现变化并**热重载**。

## 3. 音频从哪来

它抓的是**回环**（loopback）—— 也就是"扬声器正在放的东西"，不是麦克风。

* **首选 `soundcard`**：Windows 走 WASAPI loopback，Linux 走 PulseAudio / PipeWire 的
  monitor 设备。打开时**尽量采用设备自己的采样率与通道数**，避免因格式不匹配让设备重新协商。
* **次选 `sounddevice`**：`soundcard` 不灵时的备胎（Windows 的 WASAPI loopback 走它也成）。
* **都没有 / 抓不到 → demo 合成频谱**：程序会合成一段"像音乐"的频谱，画面照样是活的。
  自检（`--selfcheck`）会告诉你当前走的是哪条。

**抓哪个设备**：默认「自动」= 抓**默认输出设备**的回环；也可以在配置页下拉里**指定**某个设备
（`GET /api/audio/devices` 会枚举出来，存的就是 `backend:设备名`）。设备不存在/被拔掉时会
自动退回「自动」，不会因此起不来。

启动时还会：**先等「启动延迟」**再去碰音频设备（错开启动那一瞬间的抢占），
并且让 Chromium 带上 `--mute-audio`（我们的页面本来就没声音，别去抢设备）。

> 抓不到系统声音时先看自检：多数是"没装依赖"或"没选对回环设备"。Linux 上还需要能访问
> 声音服务（PulseAudio / PipeWire 的 monitor）；Windows 上要允许应用访问"音频回环"。

## 4. 它是怎么画出来的

* **低 / 中 / 高音各自归一化**：把频段按频率切成三块（≈250Hz / ≈4kHz 为界），每块跟一条
  "快上冲、慢回落"的参考线。⚠ 这是"低音不再永远打满"的关键 —— 以前用**全局**峰值做参考线，
  而低音通常就是全局最响的那一路，于是它永远顶在 100%；分块之后每块只看自己的相对强弱。
  三块的**占比**（`bass` / `mid` / `treble`）在归一中后乘。
* **实时预览**里会显示低/中/高音的**占比读数**（当前三块的平均电平归一化到 100%）。
* 音频 → FFT → **按对数切成 `count` 个频段** → 三块各自归一化 + 占比 + 攻击/释放平滑 →
  一串 0~1 的数；
* 这串数由 Python 以 ~50fps 推给浮层页面（`QWebEngineView`），页面用 **HTML5 Canvas** 画；
* **余晖（荧光拖尾）**：条与粒子不是每帧清掉重画，而是画到一张**旁路画布**上，每帧用 `destination-out`
  把上一帧"擦淡"一点 —— 在**透明**画布上这是做拖尾的正确姿势（画黑会把透明处填黑，降 alpha 才是淡出到透明）；
  拖尾时长由时间常数定（`appearance.afterglow`，与帧率无关）。
* **辉光**用"降采样到 1/4 → 模糊 → 用 `lighter` 叠回来"的廉价 bloom 近似（不用 `shadowBlur`，
  它对每个对象都开一次高斯，`count` 上百时必然掉帧）；
* **粒子**是复用的对象池，从频谱条顶端按能量逸出、向外散射、渐隐；
* **CRT 质感**（扫描线 / 暗角 / 轻微闪烁）由 CSS 覆盖层完成，几乎不花性能；
* 配置页的**实时预览**与桌面浮层**共用同一份渲染代码**（`web/static/js/lib/spectrum.js`），
  并轮询 `/api/spectrum` 显示**真实**的当前频谱 —— 所见即所得。

## 5. 平台说明

* **Windows**：两种模式都完整支持。「壁纸」会把窗口挂进桌面层（`WorkerW`），
  于是它在"显示桌面 / 最小化全部"时也会露出来。
* **Linux**：能跑。顶层模式最好用；「壁纸」退回"尽量置于底层"，行为因窗口管理器而异
  （Wayland 下合成器可能不完全听从，属 best-effort）。

## 6. 目录结构

```
VisualSpectrum/
├── run.py                     入口：自检 → 建 Qt → 单实例 → 浮层/音频/托盘/配置页
├── requirements.txt           运行期依赖
├── environment.yml            conda 环境（开发用）
├── VisualSpectrum.spec        手写的 PyInstaller 配置
├── assets/icon.svg            应用图标（源）
│
├── app/                       ← 桌面端
│   ├── paths.py               只读资源 vs 可写数据 vs 平台惯例位置
│   ├── config.py              配置 schema：校验 / 归一化 / 原子写 / 热重载
│   ├── audio.py               回环捕获 → FFT → 频段（含 demo 合成源）
│   ├── controller.py          编排：音频引擎 → 浮层；配置热重载
│   ├── tray.py                托盘（没有托盘宿主时安静降级）
│   ├── selfcheck.py           体检项
│   ├── log.py                 日志（文件一直在写；终端可选）
│   ├── single_instance.py     单实例：锁文件 + 本地套接字
│   └── overlay/
│       ├── window.py          浮层窗口（顶层 / 壁纸两种形态）
│       └── webview.py         WebEngine 渲染桥（推设置与每一帧）
│
├── backend/                   ← 配置页的后端
│   ├── app.py                 Flask 应用（托管 web/）
│   └── api/config_api.py      REST：meta / config / validate / reset / export / spectrum
│
├── web/                       ← 前端（原生 ES 模块，无构建步骤）
│   ├── overlay.html           浮层页（本地文件加载）
│   ├── templates/index.html   配置页外壳
│   └── static/
│       ├── css/               base.css（配置页，音乐主题）/ overlay.css（浮层）
│       └── js/
│           ├── overlay.js     浮层入口：收数据 → 转交渲染器
│           ├── main.js        配置页入口
│           └── lib/           api / dom / spectrum（共用渲染器）/ preview
│
├── tools/smoke_overlay.py     离屏建一扇浮层窗口推几帧（冒烟）
└── tests/                     pytest：配置 / 音频 / 接口 / 窗口标志
```

## 7. 开发者

```bash
conda run -n VSp python -m pytest -q                 # 跑测试
conda run -n VSp python run.py --selfcheck           # 体检
conda run -n VSp python tools/smoke_overlay.py       # 离屏冒烟（需要 PyQt6-WebEngine）
```

浮层的 console 消息会被转发进日志（`--debug` 时可见）——「动画有点掉帧」这类问题，
日志里能看到是 GPU 被降级成 CPU 光栅、还是我们自己在猛改 DOM。

## 8. 依赖与致谢

* GUI / 渲染：**PyQt6** + **PyQt6-WebEngine**（Canvas）
* 后端：**Flask**（配置页）
* 音频：**soundcard**（回环捕获）+ **numpy**（FFT）

架构与不少"踩过的坑"（WebEngine 必须早于 QApplication 导入、整屏透明表面的 alpha、
单实例、配置原子写与热重载、GPU 光栅等）参考了同作者的
**RadialMenu** 径向菜单项目。
